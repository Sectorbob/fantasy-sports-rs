# sectorbot

A Discord bot for a fantasy football league, with a small HTTP API. It can

- answer league questions in Discord: keeper costs from draft history and FantasyPros
  rankings (`!keepables`) and a randomized, bucketed draft order (`!draftorder`),
- post new entries from Twitter accounts and YouTube channels to a Discord channel (opt-in), and
- serve those feeds as RSS.

It is built on the [`fantasy-sports`](../../crates/fantasy-sports) crates; see
[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) for how it fits together.

## Running it

You need a Discord bot token ([Discord developer portal](https://discord.com/developers/applications);
enable the *message content*, *server members* and *presence* intents).

```shell
cp .env.example .env     # then fill it in
cargo run -p sectorbot   # from anywhere in the workspace; run it from apps/sectorbot so .env is found
```

### Configuration

Everything comes from environment variables, optionally loaded from a `.env` file in the working
directory.

| Variable | Required | Meaning |
|---|---|---|
| `DISCORD_TOKEN` | yes | The bot token |
| `TWITTER_COOKIE` | yes | Session cookie for the Twitter syndication endpoint (use any value if you do not enable the feed fetcher) |
| `YT_API_KEY` | yes | YouTube Data API key (any value if you do not enable the feed fetcher) |
| `ADMIN_DISCORD_USER_ID` | no | The only user allowed to run `!` commands; with it unset all commands are refused |
| `SLEEPER_LEAGUE_ID` | no | League for `!keepables` and `!draftorder`; the commands report "not configured" without it |
| `FEEDS_FILE` | no | JSON file of feeds to add to the data store at startup, see [`feeds.example.json`](feeds.example.json) |
| `ENABLE_FEED_FETCHER` | no | `true` to poll every feed and post new entries (off by default) |
| `PUBLIC_BASE_URL` | no | Base URL used in RSS links (default `http://localhost:<port>`) |
| `HTTP_SERVER_PORT` | no | Port for the HTTP API (default `8080`) |
| `HIDE_LOG_TS` | no | `true` to omit timestamps from logs (handy under systemd) |
| `RUST_LOG` | no | Log filter, for example `info` |

Secrets are never read from the repository or baked into the container image.

### Discord commands

`!ping`, `!info`, `!health` (YouTube quota used), `!keepables`, `!draftorder`,
`!set-manager <user>`, `!set-league <league>`. Only the admin user can run them.

### HTTP API

| Route | |
|---|---|
| `GET /health` | status and YouTube credits used |
| `GET /feeds` | feeds as JSON |
| `GET /feeds/{name}` | a feed as RSS; `name` is a slug of the feed's name (`Rovers News` is `rovers-news`) or its numeric id |
| `GET /leagues` | the leagues the bot knows about |

## Feeds

A feed is a list of sources (`twitter:<handle>` or `youtube:<channel id>`), a Discord destination
(`discord:<channel id>`), a polling interval in seconds and a quiet-hours window. Copy
`feeds.example.json` to `feeds.json`, edit it and point `FEEDS_FILE` at it. Feeds already in the
data store (and their entries) are left alone.

The Twitter source reads an unofficial syndication endpoint using a session cookie. It can break
at any time and may be against Twitter's terms, which is why the fetcher is opt-in.

## Deploying

A statically linked binary runs in an empty (`FROM scratch`) container. Building one needs the
musl target and a musl C compiler:

```shell
rustup target add x86_64-unknown-linux-musl
sudo apt install musl-tools          # Debian/Ubuntu
make buildd                          # builds the binary and the docker image
docker run --env-file .env -p 8080:8080 -v $PWD/data_store:/data_store sectorbot:latest-amd64
```

`systemd.service` is an example user unit. The data store is a directory (`data_store/`) of `sled`
databases in the working directory; mount or back it up to keep feeds across restarts.

## Tests

```shell
cargo test -p sectorbot
```

Fixtures in `testdata/` are synthetic ("Example Rovers" world) and regenerated by
`python3 testdata/gen_fixtures.py`; see `testdata/README.md`.
